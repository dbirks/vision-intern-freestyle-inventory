# Literature and open-source survey: Freestyle cartridge inventory

Research date: 2026-11-26. Sources and package indexes were checked on this date. This is a literature survey, not a measurement on the cabinet. The source benchmarks below differ in data, resolution, hardware, preprocessing, and evaluation; their scores and speeds are not interchangeable. In particular COCO AP is not cartridge-count accuracy. No private images were inspected.

## Decision context

There are approximately 30–40 narrow faces across two shelves, 18 identities, about 25 distinct usable frames, fisheye distortion, blur and a moving camera. The central separation is **instance recall** versus **identity**: an accurate class count requires both, and a missed face or an incorrect class each changes the count. Distinguishing Part 1/2 or AA/CC may require information that is physically absent from a blurred JPEG. Keep `unknown` as an explicit outcome, with a human review path; do not silently force every crop into one of 18 classes. A two-high NNS stack requires two instance annotations, not one tall box.

At 2048 pixels wide, shrinking the entire image to 512–704 pixels can erase fine print. Preserve original pixels for classification and test overlapping shelf tiles for localization. Tiles require coordinate remapping and duplicate reconciliation; aggressive NMS can remove touching neighbors. Avoid assuming all objects have a fixed location or that counts are constant between inventory events.

## 1. Dense shelf localization and supervised detectors

[SKU-110K (CVPR 2019)](https://arxiv.org/abs/1904.00853) targets densely packed retail objects and uses overlap-aware merging. It tests generic product detection, not recognition of particular SKUs. [Unitail's comparison (ECCV 2022)](https://www.ecva.net/papers/eccv_2022/papers_ECCV/papers/136670695-supp.pdf) lists SKU-110K as 11,748 images, ~1.73 million axis-aligned boxes and one category; SKU-110K-R adds rotated boxes. Unitail itself lists 12,244 images, ~1.78 million quadrilaterals and 1,454 categories with detection, recognition and text. Its quadrilaterals are especially relevant to rectified crops. [RP2K](https://arxiv.org/abs/2006.12634) studies fine-grained retail product classification; [RPC](https://rpc-dataset.github.io/) has catalog and checkout imagery. None establishes performance on these cartridges.

## 2. Open-vocabulary and promptable auto-labelers

- **SAM 3**, Meta, November 2025: [official page](https://ai.meta.com/research/sam3/) supports short text concepts and box exemplars for *all matching instances*, image masks and video tracking; follow-up points refine masks. [Repository](https://github.com/facebookresearch/sam3) requires CUDA 12.6+, gated weights and the [SAM License](https://github.com/facebookresearch/sam3/blob/main/LICENSE), not Apache. The repository includes the SAM 3 agent: a VLM-driven iterative prompting workflow; it has extra model/API dependencies and is not the same as a single SAM 3 forward pass. Measure latency and VRAM locally; no comparable 5090 figure established here. Test generic `cartridge box` plus visual exemplars from both shelves and visually confusable classes. Masks can provide boxes or quadrilaterals; individual touching masks and fine-print identity are not guaranteed.
- **Grounding DINO 1.5/1.6 Pro and DINO-X**: [IDEA's API repository](https://github.com/idea-research/grounding-dino-1.5-api) reports zero-shot COCO box AP 54.3/55.4 and LVIS minival AP 55.7/57.7 for 1.5/1.6 Pro. These are hosted offerings, not locally downloadable 1.5/1.6 Pro checkpoints established by the API client license. [DINO-X](https://github.com/IDEA-Research/DINO-X-API) is also an API offering; check current service terms, upload policy and costs before use. The original local `IDEA-Research/grounding-dino-tiny` is a different model, Apache-2.0, not 1.5/1.6. Do not upload cabinet frames without appropriate authorization.
- **MM-Grounding-DINO**: [official model zoo](https://github.com/open-mmlab/mmdetection/blob/main/configs/mm_grounding_dino/README.md) reports zero-shot COCO AP 50.5 for Tiny O365+GoldG+GRIT and 52.5 for Base O365+GoldG+V3Det. MMDetection code is Apache-2.0; verify each checkpoint and training-data terms. Open weights, but setup uses MMDetection/MMCV compiled dependencies. Generic text may find faces while missing items that look unlike boxes.
- **OWLv2**: [`google/owlv2-base-patch16-ensemble`](https://huggingface.co/google/owlv2-base-patch16-ensemble), Apache-2.0 model card, supports text and image-guided detection; its standard processor uses 960×960. [OWLv2 paper](https://arxiv.org/abs/2306.09683) reports 44.6 AP on rare LVIS classes for the largest model after self-training, not a result for this base checkpoint. Tiling can preserve small faces. An exemplar may match a broad package type rather than exact Part 1/2.
- **Florence-2**: [`microsoft/Florence-2-base`](https://huggingface.co/microsoft/Florence-2-base) and `microsoft/Florence-2-large`, 0.23B/0.77B, support object detection, phrase grounding and OCR; model cards list MIT. [Paper](https://arxiv.org/abs/2311.06242) describes 768-square visual inputs. Generated coordinates and text need checking for truncation, duplicates and omissions in dense scenes; no verified 5090 speed or memory figure found.
- **YOLO-World / YOLOE**: `yolov8s-worldv2.pt` is text prompted; [YOLOE](https://github.com/ultralytics/ultralytics/blob/main/docs/en/models/yoloe.md) `yoloe-26s-seg.pt` supports visual and text prompts. Ultralytics distribution is AGPL-3.0 or enterprise. At 640 pixels, official LVIS minival results for YOLOE-26s are 30.8 AP text / 28.6 AP visual, non-end-to-end protocol; these are not SKU scores. Visual prompting needs reference boxes and can be a fast proposal baseline. No verified local VRAM or speed for this exact workload.
- **T-Rex2**: [official repository](https://github.com/IDEA-Research/T-Rex) describes interactive and cross-image visual-exemplar, text and counting workflows; IDEA License 1.0 for repository, with hosted API and `dds-cloudapi-sdk==0.1.1` in its example. It is not evidence of local open weights. IDEA reports 47.6 LVIS minival AP for visual T-Rex2 in its [comparison](https://github.com/idea-research/grounding-dino-1.5-api). API privacy and latency apply.
- **Qwen3-VL and the available local VLMs**: [`Qwen/Qwen3-VL-4B-Instruct`](https://huggingface.co/Qwen/Qwen3-VL-4B-Instruct) is an explicit reproducible comparison; consult its card for Apache-2.0 and dynamic-resolution settings. [Qwen3-VL official repository](https://github.com/QwenLM/Qwen3-VL) documents spatial grounding and evaluation configurations. The provided Qwen 3.8 Flash Next and Inkling 2 Mini API identifiers, image resizing, context limits, licenses, hardware and coordinates are deployment-specific and were not verified; query the server and record them. Ask for ordered JSON boxes per shelf, then count the returned unique boxes, checking complete coverage and coordinate conventions. Generic grounding benchmark scores do not establish recall across 40 small adjacent items; output length, image downsampling and hallucinated coordinates are concrete risks. Compare whole-frame and tiled prompts. Do not treat a VLM judge as independent ground truth.

Published VRAM and inference speeds for the exact promptable models, input sizes, and GPUs above were not consistently available; measure them, including model load and number of prompts. Some models impose input resizing or token budgets, so record actual processed dimensions, not just JPEG dimensions.

## 3. Few-shot counting

[CountGD (NeurIPS 2024)](https://github.com/niki-amini-naieni/CountGD) combines text and visual exemplars; its code is [MIT](https://github.com/niki-amini-naieni/CountGD/blob/main/LICENSE), while upstream checkpoints/dependencies must be checked. [DAVE (CVPR 2024)](https://openaccess.thecvf.com/content/CVPR2024/papers/Pelhan_DAVE_-_A_Detect-and-Verify_Paradigm_for_Low-Shot_Counting_CVPR_2024_paper.pdf) detects and verifies exemplar matches. [GeCo (NeurIPS 2024)](https://arxiv.org/abs/2409.18686) combines detection and segmentation; [2026 COUNT-VID](https://www.robots.ox.ac.uk/~vgg/publications/2026/AminiNaieni26/amininaieni26.pdf) finds the best model depends on prompt type and reports GeCo strong for exemplar-only video counting. Their [official GeCo/DAVE implementation](https://github.com/lorenzopelhan/GeCo) should be pinned to a commit and its weights' terms reviewed before use.

A [benchmark comparison](https://opencodepapers-b7572d.gitlab.io/benchmarks/object-counting-on-fsc147.html) lists FSC-147 test MAE 5.74 CountGD, 7.91 GeCo and 8.66 DAVE; different prompt/preprocessing protocols and later versions can change numbers. These figures are counts per image on FSC-147, not 18-way classification. For this problem, run once per class with exemplars only as an experiment: similar labels may match the same boxes across classes, errors accumulate over 18 passes, and absent classes need false-positive control. Prefer outputs with individual locations to a bare density sum so counts can be audited and duplicates reconciled. Measure 18-pass runtime and peak VRAM; no comparable published 5090 numbers verified.

## 4. Crop identification and small text

- Freeze an encoder and compare normalized crop embeddings to multiple labeled examples per class with cosine kNN or class prototypes. [`facebook/dinov2-base`](https://huggingface.co/facebook/dinov2-base), ViT-B/14, Apache-2.0; [`facebook/dinov3-vitb16-pretrain-lvd1689m`](https://huggingface.co/facebook/dinov3-vitb16-pretrain-lvd1689m), ViT-B/16, gated under the [DINOv3 license](https://github.com/facebookresearch/dinov3/blob/main/MODEL_CARD.md); and [`google/siglip2-base-patch16-512`](https://huggingface.co/google/siglip2-base-patch16-512), 86M, 512 square, Apache-2.0, are practical comparisons. [SigLIP 2](https://huggingface.co/blog/siglip2) also offers aspect-ratio-aware NaFlex variants. CLIP's [`openai/clip-vit-base-patch32`](https://huggingface.co/openai/clip-vit-base-patch32) provides a 224-square baseline. A linear probe can learn a better boundary but needs more independent labeled views and validation than kNN. DINOv3 reports ImageNet and dense-feature transfer scores in its model card; those are not evidence for Part 1/2 discrimination. Measure accuracy on ground-truth crops separately from detection. VRAM/speed varies with batching and crop resolution; no exact hardware figure is asserted.
- Product retrieval uses a reference gallery rather than retraining whenever a SKU changes; Unitail's detection/read/match formulation and RP2K illustrate the distinction between product recognition and generic detection. Capture several **in-camera** views per class, including blur and edge distortion; clean catalog images alone create a domain shift. Preserve native pixels and compare tight face crops with small context and optional perspective-normalized crops. Per-class top-1, macro recall, hard-pair confusion and unknown rejection matter more than overall accuracy.
- OCR: [PP-OCRv5](https://github.com/PaddlePaddle/PaddleOCR/blob/main/docs/version3.x/algorithm/PP-OCRv5/PP-OCRv5.en.md) reports 0.8679 printed-English recognition on its internal set for `PP-OCRv5_server_rec`. [PP-OCRv6](https://github.com/PaddlePaddle/PaddleOCR/releases) released 2026-06-11 with `paddleocr` 3.7.0, reports 34.5M parameters for medium and 0.13 s on A100 for its stated pipeline; the code is Apache-2.0. Check individual weights. Run `PP-OCRv5_server_det` + `PP-OCRv5_server_rec` and/or PP-OCRv6 medium on native-resolution crop or rectified text region, and compare VLM transcription. Use exact lexicon matches for Part 1/2 and AA/CC as *evidence*, including a missing/unreadable state. Upscaling cannot recreate lost characters; measure character/word accuracy on manually transcribed hard crops and do not accept plausible VLM guesses as text.

## 5. Fisheye, rotated boxes and augmentation

[FishEye8K](https://openaccess.thecvf.com/content/CVPR2023W/AICity/html/Gochoo_FishEye8K_A_Benchmark_and_Dataset_for_Fisheye_Camera_Object_Detection_CVPRW_2023_paper.html) has 8,000 traffic images and 157k boxes, not retail shelves. [2025 fisheye challenge work](https://openaccess.thecvf.com/content/ICCV2025W/AICity/html/Tsai_Enhanced_Fisheye_Object_Detection_via_YOLO_Ensemble_Learning_and_Weighted_ICCVW_2025_paper.html) reports F1 0.6413 with a calibration-free ensemble on FishEye1Keval. [SDANet](https://ieeexplore.ieee.org/document/10814722/) learns distortion-aware features and augmentation. These support testing adaptation, not a claim of superiority for a particular cabinet.

Calibrate this exact lens, sensor mode, crop and resolution with a suitable target; 160° alone does not determine intrinsics or distortion coefficients. Compare original distorted frames against calibrated undistortion, accounting for edge cropping, interpolation, black borders and reduced effective resolution. Keep labels in the correct coordinate system; for non-linear warps transform sampled boundaries, not only two box corners. Do not invent calibration parameters. Axis-aligned boxes are cheap and likely adequate for initial counts; add quadrilateral corners or oriented boxes for slanted examples when overlap or crop contamination hurts. Fisheye curves may make even an oriented rectangle approximate; a planar homography is only locally appropriate after distortion correction. [OpenCV fisheye calibration](https://docs.opencv.org/4.x/db/d58/group__calib3d__fisheye.html) and [Ultralytics OBB](https://docs.ultralytics.com/tasks/obb/) document implementations.

## 6. Annotation efficiency and validation

Use Vision Intern's VLM label → VLM judge → RF-DETR workflow as a proposal system, not ground truth. Manually correct **all** boxes and labels in the evaluation frames, including misses, false positives, shelf boundaries, occlusions, unknown/unreadable text and the two-high stack. Define whether partially visible faces count and record per-instance visibility. Seed with a few fully corrected diverse frames, then select new frames by detector disagreement, low confidence, uncommon classes, distortion, blur and shelf coverage; correct all instances in selected images rather than only confident proposals. Record correction minutes and number of boxes, not just epochs. Active learning cannot manufacture independent scenes out of near-duplicates.

[Simple Copy-Paste](https://arxiv.org/abs/2012.07177) reports +1.5 box AP on COCO under its experimental setup. For retail, paste segmented/rectified examples in plausible shelf positions with realistic scale, overlap, lighting, blur and fisheye warp; maintain exact boxes and identity. This is a hypothesis for this cabinet, not a demonstrated improvement. Compare real-only versus synthetic-plus-real under identical independent holdouts, and never paste test content into training. Overly clean edges, repeated reference crops and unrealistic label placements can cause shortcut learning. Synthetic counts and class balance must include absent and rare classes.

## 7. Burst / temporal fusion

For each burst with a stationary inventory, prefer several frames with complementary sharpness. Register shelves locally or associate detections by geometry and appearance; fuse per-track class evidence, and count **unique tracks** once. Blur can change which face is readable. [ByteTrack](https://github.com/FoundationVision/ByteTrack) associates even low-score boxes and reports MOT17 test 80.3 MOTA, 77.3 IDF1 and 30 FPS on V100 in its paper, for pedestrian tracking—not swinging fisheye shelves. SAM 3 video tracking is another candidate. Camera swing and parallax can break global homographies, while NNS stacking and near-identical neighbors can cause ID switches or merged tracks. Reset when cabinet contents change. Evaluate single best frame versus 3/5-frame fusion on held-out bursts with manually linked IDs, reporting count error, track fragmentation, ID switches, runtime and latency; do not sum counts over frames. If only isolated frames exist, this remains a proposed future experiment.

## Shared experiment protocol

1. Split by **capture session/burst and inventory state**, not by crop or adjacent frame. Reserve an untouched test group before tuning. With ~25 frames, report each test frame, paired differences and bootstrap intervals by independent session; if too few sessions exist, use grouped cross-validation for development and explicitly state that independent generalization is unmeasured. One cabinet cannot establish cross-cabinet generalization. Never reuse a test crop as an exemplar.
2. Fully annotate each evaluable instance with box, 18-way class or unknown, shelf, and readability; record class counts including zero. For OCR test, transcribe discriminating text where visible. Annotation rules must specify occlusion, boundaries and stacking. Track exact label effort.
3. Report class-agnostic recall/precision and AP at IoU 0.5 plus AP50:95, matched crop identity accuracy and hard-pair confusion, end-to-end per-class count MAE, total absolute count error, exact inventory rate, and false positives for absent classes. Specify matching, IoU, confidence, NMS, maximum detections and unknown handling. Report error separately for blur, image edge, shelf and rare classes; show detection oracle and classification oracle to locate the bottleneck.
4. Freeze train/tuning/test assignment and use identical input views, thresholds selected on development only, and label budgets for paired comparisons. Measure model initialization, peak allocated and reserved GPU memory, warm median/p95 end-to-end latency including tiling, OCR, VLM calls and postprocessing; record GPU contention, precision, batch size, actual input dimensions, checkpoint hash and software environment. Repeat after excluding warm-up. No source above establishes an out-of-the-box speed or memory budget for this pipeline.

## Candidate architectures to compare

Package versions below were verified against [PyPI JSON](https://pypi.org/) on 2026-11-26: `rfdetr==1.12.1`, `transformers==5.24.1`, `torch==2.15.0`, `ultralytics==8.4.220`, `paddleocr==3.7.0`, `opencv-python==5.1.0.95`, `scikit-learn==1.9.1`, `supervision==0.32.3`, `openai==3.60.0`. These are *available versions*, not a tested compatible lockfile; select CUDA-compatible PyTorch/Paddle wheels and resolve transitive constraints in isolated environments. The PyPI `paddlepaddle-gpu` index returned 2.6.2, which is not a claim of compatibility with PaddleOCR 3.7; follow [Paddle's GPU installation instructions](https://www.paddlepaddle.org.cn/install/quick) for a compatible 3.x wheel. `sam3==0.1.4` exists on PyPI, but its provenance/equivalence to Meta's repository was not verified: use the official repository and pin a commit instead. Licenses apply separately to packages, weights and data.

**A. Direct VLM grounding.** Use the existing local Qwen 3.8 Flash Next and Inkling 2 Mini endpoints, recording exact server model IDs, with `openai==3.60.0`; optionally compare `Qwen/Qwen3-VL-4B-Instruct` with `transformers==5.24.1` and a compatible `torch==2.15.0`. Request boxes and labels in JSON per shelf, with explicit unknown and original-pixel mapping; also test tiled inputs. **Labels:** no training labels, but complete evaluation annotations and a short class reference sheet. **Strength/risk (hypothesis):** minimal setup and potentially useful text reasoning; omissions, hallucinations, small print and serialized output are likely failure points. **Experiment:** same held-out frames and image budget, independently score box recall, crop identity, JSON validity and count error against both endpoint models; repeat prompts to measure variability.

**B. Prompted proposals plus crop retrieval.** Use Meta SAM 3 official checkpoint `sam3.pt` from its gated [repository](https://github.com/facebookresearch/sam3), or `google/owlv2-base-patch16-ensemble` via `transformers==5.24.1`; classify native crops using `google/siglip2-base-patch16-512`, cosine kNN with `scikit-learn==1.9.1`, and optionally PP-OCRv5. **Labels:** one or several generic proposal exemplars plus a small labeled gallery per class and full evaluation labels. **Strength/risk:** avoids detector training; proposal misses and visually near-identical labels can dominate. **Experiment:** measure proposal recall at matched annotation time for text versus visual prompts, then oracle crops versus predicted crops, varying 1/3/5 independent exemplars per class. SAM 3 requires its own official environment and license; OWLv2 can run separately.

**C. Class-agnostic trained detector plus crop identifier.** Fine-tune `RFDETRSmall` COCO weights using `rfdetr==1.12.1`, `supervision==0.32.3`; use `facebook/dinov2-base` and/or SigLIP 2 gallery kNN (`transformers==5.24.1`, `scikit-learn==1.9.1`), with `paddleocr==3.7.0` for ambiguous text. **Labels:** complete class-agnostic boxes on selected training frames plus labeled reference crops; optionally VLM-propose and human-correct. **Strength/risk:** pools all objects for localization and permits adding classes without retraining detector; crop contamination and hard-pair ambiguity remain. **Experiment:** learning curves at 3/6/12 fully corrected frames, whole frame versus shelf tiles; compare ground-truth versus predicted crops and OCR on/off. Compare D-FINE `dfine_hgnetv2_l_coco` in a separate pinned official-repository environment if setup permits.

**D. End-to-end 18-class detector.** Fine-tune `RFDETRSmall` with `rfdetr==1.12.1` and compare `yolo11s.pt` / `yolo26s.pt` with `ultralytics==8.4.220` under their respective licenses. **Labels:** every visible instance's box and class in training frames; mark unreadable instances and exclude or handle consistently rather than inventing labels. **Strength/risk:** simple one-pass deployment; extremely few independent views per class and downsampling can hide distinguishing text. **Experiment:** identical corrected frames and splits as C, tune resolution and thresholds on development, compare class-agnostic localization and class counts; inspect Part 1/2, AA/CC and stacked NNS separately.

**E. Shelf-structure-aware model.** Use C's `RFDETRSmall` proposals, `opencv-python==5.1.0.95` shelf/row geometry, SigLIP 2 crop classifier and a constrained left-to-right assignment with a separate vertical tier for stacked items. **Labels:** C's boxes and identities plus shelf/tier assignments on training and evaluation frames. **Strength/risk (hypothesis):** ordering and adjacency can expose gaps and duplicates; fixed slot widths or assumed planograms can fail at variable spacing, occlusion, edge distortion and inventory changes. **Experiment:** compare identical C predictions with and without geometry; measure missed/doubled faces and two-high errors, and permit empty/unknown slots rather than forcing a count.

**F. Burst fusion.** Apply C to each frame, associate with ByteTrack via `supervision==0.32.3` or an explicitly pinned [official ByteTrack](https://github.com/FoundationVision/ByteTrack) implementation; aggregate crop scores over unique tracks and route uncertain tracks for review. **Labels:** C's training data plus held-out bursts with instance links and counts. **Strength/risk:** can recover a sharp view without extra detector labels; moving camera, repeated boxes and inventory changes cause ID switches and double counts. **Experiment:** on the same held-out bursts compare one frame, best sharp frame, and 3/5-frame fusion, with unique-track count MAE, ID switches, p95 latency and peak memory. This requires collecting bursts if unavailable.
