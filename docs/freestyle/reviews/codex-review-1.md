# Freestyle correctness review

## Findings

1. **Critical — Identification evaluation can train on the test set and split bursts across gallery and query.** `freestyle/identify/cli.py:140`, `:275`, `:291` and `:359`: both `--groups` and `--split` are optional. Without them, every filename becomes a separate group, and leave-one-group-out fits on every other image in the NPZ, including test and exclude images. Even `--split test` fits the gallery on the other test groups. Thus similar frames of the same event can appear on both sides and test labels train the classifier. CPU repro: `_resolve_groups_and_splits(['cab/event/a.jpg','cab/event/b.jpg'], ['1','2'], None)` returned `(['cab/event/a.jpg', 'cab/event/b.jpg'], [None, None])`. Separately, `freestyle/pipeline.py:31` fits every gallery row without checking split or query overlap; the archive produced by `run_embed` includes every annotation in its input. **Fix:** require validated group and split provenance, use train-only galleries for val/test queries, enforce group disjointness and reject test/exclude gallery rows. Reserve LOGO for explicitly selected training groups.

2. **Major — VLM's default coordinate interpretation contradicts its own prompt.** `freestyle/vlm_ground.py:43` and `:72`: the prompt requests 0–1000 coordinates, but `auto` treats values that fit an image smaller than 1000 pixels as pixel coordinates. With an 800×800 tile and response `[100,100,500,500]`, CPU repro returned `auto: [100, 100, 500, 500]` versus `norm1000: [80, 80, 400, 400]`. This shifts and enlarges boxes, affecting AP and identity crops; resizing via `max_side` makes this especially likely. **Fix:** default to `norm1000` for this prompt, or explicitly specify and validate the model's coordinate convention; never infer ambiguous units from magnitude.

3. **Major — Composed tiled detector discards predicted identities.** `freestyle/pipeline.py:60`, `:89`, `:99`; `freestyle/infer/detector.py:23`: TiledDetector emits `category_id`, while Pipeline only reads `class`. With no separate identifier every detection becomes `unknown`, including a class-aware detector. CPU repro with a detector returning `{'box':[0,0,10,10], 'score':0.9, 'category_id':1}` produced `class: unknown, id_score: 0.0`. **Fix:** adapt backend indices through the detector class names and COCO category mapping into class slugs and identity scores before pipeline counting; explicitly handle class-agnostic detectors.

4. **Major — Identity rejection threshold does not reject anything.** `freestyle/pipeline.py:99`, `freestyle/count/aggregate.py:18`, `:37`: `identity_thr` controls neighbour voting only; the original class remains in both detections and counts when confidence is below threshold. CPU repro with `class='coke', id_score=0.1, identity_thr=0.5` returned `{'coke': 1}`. Predictions likewise carry the low-confidence known category, biasing ID and inventory results. **Fix:** convert low-confidence identities to `unknown` before counting and prediction serialization, preserving the original proposal separately if needed; make applied votes and their scores consistent.

5. **Major — Exact inventory ignores unknown and generic false positives.** `freestyle/eval/metrics.py:171`, `:588`, `:638`: class vectors exclude `unknown` and `cartridge` when catalog classes exist, and exact inventory checks only those vectors. CPU repro on an empty GT image with one `unknown` prediction returned `total_count_mae: 1.0`, `per_class_count_mae: 0.0`, and `exact_inventory_rate: 1.0`. An extra generic detector output has the same effect. **Fix:** define special-class inventory semantics explicitly and ensure unmatched extra unknown/generic detections cannot yield exact inventory; include the total count condition or explicit special-class counts as appropriate.

6. **Major — Group bootstrap silently defaults to images, overstating precision.** `freestyle/eval/evaluate.py:97`, `freestyle/eval/metrics.py:102`: the documented command does not supply `--groups`; absent embedded group metadata, each frame becomes its own bootstrap group. Adjacent frames from one event or `local/blur` are correlated, so the reported 95% interval is based on the wrong independent units. The group resolver repro in finding 1 demonstrates the corresponding filename fallback; the metrics resolver uses the same fallback. **Fix:** require complete explicit group mapping or verified group IDs on every image, and fail on unresolved groups rather than silently treating frames as independent.

7. **Major — Threshold selection can use test labels.** `freestyle/eval/evaluate.py:135`: the guard rejects test selection only if the selection GT path resolves to the evaluation GT path *and* the latter looks like test. A copied test JSON, a differently named test file, or a test selection file used to evaluate another split bypasses it. The best-F1 threshold then uses test annotations. **Fix:** validate the selection dataset's image/group membership against the split map and require every selection image to be val, disjoint from evaluated test groups; fail closed when provenance is absent.

8. **Major — Training tiles contain unlabelled visible cartridges.** `freestyle/train/export_tiles.py:63`: every tile is saved, but a partially intersecting annotation is dropped when its visible fraction is below the default 0.6. A cartridge spanning a tile boundary can therefore be visible in a training tile while treated as background, teaching false negatives on the very border cases the contract counts. Evidence: the intersection is computed at lines 67–69 and `continue` at line 70 removes the annotation without masking or dropping the tile. **Fix:** annotate clipped visible portions, mask/ignore them using a mechanism supported by the actual trainer, or exclude affected tiles. Verify the handling of validation tiles as well.
